## 家庭服务器优化

对于 **8GB 内存** 运行 GitLab 来说，确实处于一个“刚刚好”的临界点。GitLab 官方推荐的最低内存其实就是 4GB（仅能运行）到 8GB（相对流畅）。

由于 **GitLab** 是一个由许多后台服务（如数据库、缓存、监控等）组成的“巨兽”，如果它吃掉了太多内存，您的 **Samba** 传输速度可能会因为系统频繁调用交换空间（Swap）而变得非常慢。

既然是家庭使用，我建议您对 GitLab 进行简单的**“瘦身”**，给 Samba 腾出更多呼吸空间：

### 1. 优化 GitLab 的内存占用

GitLab 默认会开启很多企业级监控工具，家庭环境下完全可以关掉。

1. 打开配置文件： `sudo nano /etc/gitlab/gitlab.rb`

2. **关闭不必要的监控（Prometheus）：** 搜索并修改以下参数（去掉前面的 `#`）：

   ```ruby
   prometheus['enable'] = false
   alertmanager['enable'] = false
   node_exporter['enable'] = false
   ```
   
3. **减少后台工作进程：**

   ```ruby
   sidekiq['max_concurrency'] = 10
   postgresql['max_connections'] = 50
   ```
   
4. **应用配置（需要几分钟）：** `sudo gitlab-ctl reconfigure`

这样做通常能帮您省下 **1GB - 2GB** 的内存，这对 Samba 处理 14 台电脑的高频访问至关重要。

------

### 2. 为 Samba 设置“缓冲区”

在 8GB 内存的机器上，如果 Windows 25H2 正在拷贝大文件，可以给 Samba 增加一些优化参数，提高读写稳定性。

在 `/etc/samba/smb.conf` 的 `[global]` 段落添加：

```ini
socket options = TCP_NODELAY IPTOS_LOWDELAY
read raw = yes
write raw = yes
```

------

### 3. 必须要有的“保险”：增加 Swap 交换文件

如果 14 台电脑同时访问导致 8GB 内存瞬间爆满，没有 Swap 会导致系统直接死机或强制重启。建议在 Ubuntu 上设置一个 **8GB 的交换文件** 作为缓冲：

```bash
sudo fallocate -l 8G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
# 永久生效：将其添加到 /etc/fstab 末尾
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

------

### 💡 宅家的“极客”快乐

您有 14 台笔记本，这种 23H2、24H2、25H2 加上 Ubuntu 的混搭环境，最适合玩**“内网穿透”**或**“自动化备份”**了。

既然您现在已经有了 **GitLab (管理代码/配置)** + **Samba (管理大文件)**，您的家庭数字中心基本成型了。
