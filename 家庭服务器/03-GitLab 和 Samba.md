## GitLab 和 Samba

在同一台 Ubuntu 机器上同时运行 **GitLab** 和 **Samba**，相当于让这台电脑兼任了“版本控制中心”和“文件共享中心”。对于您这种家里有 14 台电脑的高阶玩家，这种做法有三个巨大的优势：

### 1. 为什么“GitLab + Samba”是绝配？

- **各司其职：** **GitLab** 负责管理您的配置文件、代码和文档（那些需要历史记录、怕改乱的文件）；**Samba** 负责存放游戏安装包、高清视频、驱动程序（那些很大、不需要版本管理的文件）。
- **统一存储：** 您的所有数据都集中在一台服务器上，不仅方便管理，将来做数据备份时，只需要备份这一台机器就行了。
- **内网带宽起飞：** 既然是内网互联，14 台电脑访问 Samba 共享盘的速度取决于您的路由器和网线。如果是千兆内网，拷贝大文件的速度能达到 **110MB/s** 左右，比用 U 盘快多了。

------

### 2. 进阶玩法：让 Samba 访问 GitLab 的数据

既然它们在同一台机器上，您可以实现一个很酷的功能：

- 您可以把 **GitLab 的工作目录** 映射给 **Samba**。
- **场景：** 您在 Windows 25H2 上用记事本直接修改 Samba 盘里的代码，改完后，回到 Ubuntu 或者用网页版 GitLab 点击提交（Commit）。
- **注意：** 这样做时，请务必保证 Samba 的用户和 GitLab 文件夹的属主一致，否则可能会遇到权限报错（Permission Denied）。

------

### 3. 给 14 台笔记本玩家的特别提醒

在同一台机器上跑这两个服务，有几点需要注意：

- **内存分配：** GitLab 是个“内存大户”（尤其是其中的 Prometheus 和 Sidekiq 进程）。既然您还要跑 Samba 供多台设备连接，建议这台 Ubuntu 至少拥有 **8GB 或以上** 的内存，否则连接多了可能会卡顿。
- **磁盘 I/O：** 如果 14 台电脑同时从 Samba 拷文件，硬盘压力会很大。如果可能的话，给这台 Ubuntu 装一块 **SSD** 作为缓存或者系统盘。
- **25H2 的自动挂载：** 既然您的 25H2 已经就绪，建议在映射磁盘时勾选 **“登录时重新连接”**。

------

### 4. 下一步优化：安装一个“仪表盘”

既然您家里设备这么多，管理起来也是个乐趣。我建议您在 Ubuntu 上顺手装一个 **Dashboard**（如 **Cockpit**）：

- **安装命令：** `sudo apt install cockpit`
- **效果：** 您在任何一台笔记本的浏览器输入 `http://Ubuntu的IP:9090`，就能看到这台服务器的 CPU、内存占用，还能直接管理 Samba 服务和查看 GitLab 状态。

------

**总结：** 在一台机器上跑两个服务是非常成熟的做法。只要硬件扛得住，这就是最省心的方案。
